# Submission draft — AgntID Agent Security Challenge, 28 Nov 2026

## Project

**AgntID Allowance Proxy** — a working implementation of the AgntID
runtime access-control model (Intent + Policy → per-tool-call Access
Decision), with the NEAR Agent Allowance Guard contract
(`guard.aag7734b.testnet`) as the money-enforcement backend.

Repo: https://github.com/buahrasa01-hub/agntid-allowance-proxy

## Category strategy

- **Primary: Best Real-World Agent Security Use Case.** A real agent loop,
  a real guard, real on-chain enforcement — not a slide deck. The demo
  shows the exact failure AgntID describes (task: "summarize Doc A",
  agent drifts to Doc B) being blocked, plus a money move being stopped
  twice over (proxy pre-check, then the contract panic).
- **Secondary: Best Intent Exploration.** The computed 3×7 matrix in
  `SCENARIOS.md` (tasks × actions, generated by running the guard), with
  notes on the surprising cells.
- **Tertiary: Best Security Insight & Product Discovery.** The money
  stage reports every failing check at once instead of only the first,
  and the demo documents the live-vs-recorded distinction honestly
  (cap/allowlist panics are recorded e2e evidence; live panics say
  "revoked" because the allowance is revoked).

## Demo script (5 scenes, ~20–30 s each)

1. **Read Doc A — ALLOW.** Task "summarize Doc A". The guard passes
   policy + intent; the brief is read and summarized.
2. **Read Doc B — DENY (intent).** The agent drifts to the private note.
   Guard: `resource 'doc-b' not in intent resources ['doc-a']`. The file
   is never opened.
3. **Delete Doc A — DENY (policy).** The task "summarize Doc A" lists
   only `readDoc`; `deleteDoc` is not in the task's tool list at all, so
   the guard stops it before intent is even considered. Doc A intact.
   (The intent-stage write/delete denial is shown in the computed matrix
   in `SCENARIOS.md`, where the task lists every tool.)
4. **Spend 0.80 NEAR — DENY (money).** Remaining cap is 0.75 NEAR.
   Guard lists every failing check (revoked + over-cap). A live on-chain
   attempt panics; the verbatim panic is shown.
5. **Spend 0.01 NEAR after revoke — DENY (money + contract).** Live
   on-chain attempt panics `allowance has been revoked`. Spend log still
   has exactly 1 entry — no funds moved.
